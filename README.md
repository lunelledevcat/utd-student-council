# สภานักเรียนโรงเรียนอุตรดิตถ์ — Website

Next.js (App Router, TypeScript) + Tailwind v4 + Motion + GSAP ScrollTrigger. Design tokens mirror the Figma file
`UTD Student Council Website`. Decisions and placeholders: see [NOTES.md](NOTES.md).

## Run

Runs on **Cloudflare Workers** (OpenNext) with **D1** (database), **R2** (photos), **KV** (IP bans), Workers Rate Limiting
and **Auth.js** (Google sign-in). Plan, decisions and risks of the move from Vercel + Supabase: [NOTES.md](NOTES.md).

```bash
npm install
cp .env.example .dev.vars                               # local values (gitignored) — see "ตั้งค่า env" below
npx wrangler d1 migrations apply utd-council --local     # local database (drizzle/*.sql)
npm run preview                                          # build + run on workerd: http://localhost:8790
npm run test:unit                                        # access rules of the data layer (real D1)
npm run test:e2e                                         # Playwright on workerd with its own local D1/R2/KV
npm run security:check                                   # all security checks (SECURITY.md)
npm run deploy                                           # build + deploy to Cloudflare (after the setup below)
```

Windows: the build works without Developer Mode (`scripts/win-symlink.cjs` turns OpenNext's symlinks into junctions).

## Cloudflare: first deploy (ทำครั้งเดียว ตามลำดับ)

1. **Login**: `npx wrangler login` (เปิดเบราว์เซอร์ให้กดอนุญาต) แล้วเช็กด้วย `npx wrangler whoami`
2. **สร้าง D1**: Dashboard → Storage & Databases → D1 → Create → ชื่อ `utd-council` → คัดลอก *Database ID* ไปใส่
   `wrangler.jsonc` → `d1_databases[0].database_id` (หรือ `npx wrangler d1 create utd-council`)
3. **สร้าง R2**: R2 → Create bucket → ชื่อ `utd-council-media` (ไม่ต้องเปิด public access)
   - ถ้าจะให้อัปโหลดตรงจากเบราว์เซอร์ (เร็วกว่า): R2 → bucket → Settings → CORS policy → อนุญาต `PUT` จาก origin ของเว็บ
     (เช่น `https://utd-student-council.<subdomain>.workers.dev`) header `content-type`; แล้วสร้าง R2 API token
     (Object Read & Write เฉพาะ bucket นี้) และใส่ `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` ด้วย
     `wrangler secret put` — ถ้าไม่ใส่ ระบบอัปโหลดผ่าน Worker แทน (ทำงานได้เหมือนกัน)
4. **สร้าง KV**: Storage & Databases → KV → Create → ชื่อ `utd-council-bans` → คัดลอก *ID* ไปใส่ `kv_namespaces[0].id`
5. **ตาราง**: `npx wrangler d1 migrations apply utd-council --remote`
6. **ย้ายข้อมูลเดิม** (ถ้ามี): `node scripts/migrate-supabase-to-d1.mjs --remote` (อ่านจาก Supabase ด้วยค่าใน .env.local, เขียนซ้ำได้)
7. **ค่าลับ** (ทีละตัว ระบบจะถามค่า): `npx wrangler secret put APP_SECRET` แล้ว `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`,
   `TURNSTILE_SECRET_KEY` (+ R2 keys ถ้าใช้)
8. **ค่าไม่ลับ**: แก้ `wrangler.jsonc` → `vars` (`NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `ADMIN_EMAILS`, `ALLOWED_EMAIL_DOMAIN`)
9. **Google**: Google Cloud Console → APIs & Services → Credentials → OAuth client (Web) → *Authorized redirect URIs* เพิ่ม
   `<SITE_URL>/api/auth/callback/google` (ของ Supabase เดิมยังไม่ต้องลบ จนกว่าจะปิด Supabase)
10. **Turnstile**: Cloudflare → Turnstile → widget เดิม → Hostname management → เพิ่ม hostname ใหม่ (workers.dev / โดเมนจริง)
11. **Deploy**: `npm run deploy` → เปิด `/th/admin/setup` ด้วยบัญชี admin: ทุกค่าและ bindings ต้องเป็น ✅

## ตั้งค่า env หาจากไหน

เครื่องตัวเอง: คัดลอก `.env.example` เป็น `.dev.vars` แล้วใส่ค่า · Cloudflare: ค่าลับใช้ `npx wrangler secret put <ชื่อ>`, ค่าไม่ลับอยู่ใน `wrangler.jsonc` → `vars`
สถานะทุกค่า + bindings (D1/R2/KV/rate limit) ดูได้ที่ `/admin/setup` (admin เท่านั้น ไม่แสดงค่าจริง)

### `APP_SECRET` — จำเป็นตอนใช้งานจริง · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** กุญแจลับของแอป ใช้เซ็นโทเคน API อายุสั้น ลิงก์อัปโหลด/พรีวิวรูป และเป็นเกลือตอนแปลง IP เป็นค่าแฮช
- **หาจากไหน:** สร้างเอง: node -e "console.log(require('crypto').randomBytes(32).toString('base64'))" แล้วใส่ด้วย npx wrangler secret put APP_SECRET (เครื่องตัวเองใส่ใน .dev.vars) (https://developers.cloudflare.com/workers/configuration/secrets/)
- **ถ้าไม่ใส่:** dev → ใช้คีย์ชั่วคราวสำหรับ dev · production → อัปโหลดรูปและส่งเสียงถึงสภาไม่ได้ (error)

### `AUTH_SECRET` — จำเป็นตอนใช้งานจริง · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** กุญแจลับของ Auth.js ใช้เข้ารหัสคุกกี้ระหว่างล็อกอิน
- **หาจากไหน:** สร้างเองแบบเดียวกับ APP_SECRET (คนละค่า) แล้ว npx wrangler secret put AUTH_SECRET (https://authjs.dev/getting-started/deployment#auth_secret)
- **ถ้าไม่ใส่:** dev → ล็อกอินไม่ได้ · production → ล็อกอินไม่ได้

### `AUTH_GOOGLE_ID` — จำเป็นตอนใช้งานจริง · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** Client ID ของ OAuth client ใน Google Cloud (ล็อกอินด้วย Google)
- **หาจากไหน:** Google Cloud Console → APIs & Services → Credentials → OAuth client (Web) → Client ID; เพิ่ม Authorized redirect URI: <SITE_URL>/api/auth/callback/google แล้ว npx wrangler secret put AUTH_GOOGLE_ID (https://console.cloud.google.com/apis/credentials)
- **ถ้าไม่ใส่:** dev → ปุ่มล็อกอินปิดอยู่ · production → ล็อกอินไม่ได้

### `AUTH_GOOGLE_SECRET` — จำเป็นตอนใช้งานจริง · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** Client secret ของ OAuth client เดียวกัน
- **หาจากไหน:** หน้าเดียวกับ Client ID → Client secret แล้ว npx wrangler secret put AUTH_GOOGLE_SECRET (ห้ามใส่ในไฟล์ที่ commit) (https://console.cloud.google.com/apis/credentials)
- **ถ้าไม่ใส่:** dev → ปุ่มล็อกอินปิดอยู่ · production → ล็อกอินไม่ได้

### `TURNSTILE_SECRET_KEY` — จำเป็นตอนใช้งานจริง · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** คีย์ลับ Turnstile ตรวจว่าผู้ส่งฟอร์มเป็นคน
- **หาจากไหน:** Cloudflare → Turnstile → widget เดิม → Settings → เพิ่ม hostname ใหม่ (workers.dev / โดเมนจริง) → Secret key แล้ว npx wrangler secret put TURNSTILE_SECRET_KEY (https://dash.cloudflare.com/?to=/:account/turnstile)
- **ถ้าไม่ใส่:** dev → ใช้คีย์ทดสอบ (ผ่านเสมอ) · production → ส่งเสียงถึงสภาไม่ได้

### `R2_ACCOUNT_ID` — ไม่บังคับ · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** Account ID ของ Cloudflare ใช้สร้างลิงก์อัปโหลดตรงเข้า R2 (presigned)
- **หาจากไหน:** Cloudflare → R2 → Overview → Account ID แล้ว npx wrangler secret put R2_ACCOUNT_ID (https://dash.cloudflare.com/?to=/:account/r2/overview)
- **ถ้าไม่ใส่:** dev → อัปโหลดผ่าน Worker แทน (ทำงานปกติ) · production → อัปโหลดผ่าน Worker แทน (ทำงานได้ ช้ากว่าเล็กน้อย)

### `R2_ACCESS_KEY_ID` — ไม่บังคับ · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** Access Key ID ของ R2 API token (Object Read & Write เฉพาะ bucket utd-council-media)
- **หาจากไหน:** Cloudflare → R2 → Manage API tokens → Create API token → Object Read & Write → bucket utd-council-media แล้ว npx wrangler secret put R2_ACCESS_KEY_ID (https://dash.cloudflare.com/?to=/:account/r2/api-tokens)
- **ถ้าไม่ใส่:** dev → อัปโหลดผ่าน Worker แทน · production → อัปโหลดผ่าน Worker แทน

### `R2_SECRET_ACCESS_KEY` — ไม่บังคับ · **ลับ** — wrangler secret put
- **ใช้ทำอะไร:** Secret Access Key ของ token เดียวกัน
- **หาจากไหน:** แสดงครั้งเดียวตอนสร้าง token แล้ว npx wrangler secret put R2_SECRET_ACCESS_KEY (https://dash.cloudflare.com/?to=/:account/r2/api-tokens)
- **ถ้าไม่ใส่:** dev → อัปโหลดผ่าน Worker แทน · production → อัปโหลดผ่าน Worker แทน

### `NEXT_PUBLIC_SITE_URL` — จำเป็นตอนใช้งานจริง · wrangler vars (ไม่ลับ)
- **ใช้ทำอะไร:** ที่อยู่เว็บจริง (แผนที่เว็บ, metadata)
- **หาจากไหน:** URL หลัง deploy เช่น https://utd-student-council.<subdomain>.workers.dev หรือโดเมนจริง ใส่ใน wrangler.jsonc → vars (https://developers.cloudflare.com/workers/configuration/routing/)

### `NEXT_PUBLIC_TURNSTILE_SITE_KEY` — จำเป็นตอนใช้งานจริง · wrangler vars (ไม่ลับ)
- **ใช้ทำอะไร:** Site key ของ Turnstile (แสดงในหน้าเว็บ)
- **หาจากไหน:** Cloudflare → Turnstile → widget เดิม → Site key ใส่ใน wrangler.jsonc → vars (https://dash.cloudflare.com/?to=/:account/turnstile)

### `ALLOWED_EMAIL_DOMAIN` — ไม่บังคับ · wrangler vars (ไม่ลับ)
- **ใช้ทำอะไร:** โดเมนอีเมลที่ล็อกอินได้

## Scraping protection (what exists)

1. **`proxy.ts`**: blocks empty UA, scraper tools (curl, wget, python-requests, scrapy, HTTrack, Go-http-client, headless...) and AI
   crawlers with 403; rate limit per IP (pages 600/min — a school shares one NAT address —, API 60/min -> 429; sign-in 5 / 15 min in D1); verifies Googlebot/Bingbot by reverse DNS;
   honeypot + scanner paths ban the IP for 1h; per-request CSP nonce.
2. **`app/robots.ts`**: search engines allowed; AI/dataset crawlers disallowed; `/api/`, `/admin/`, `/_hp/` disallowed. `X-Robots-Tag: noai, noimageai`.
3. **APIs**: no endpoint returns everything (page size capped at 20); requires same-origin + 5-minute HMAC token from `/api/token`.
   Member data is name/role/grade only. `/voice` stores IP as a salted hash, with honeypot field, zod validation, 3 submits / 10 min / IP, Turnstile.
4. **Headers** (`next.config.ts` + `proxy.ts`): CSP, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, nosniff, Referrer-Policy, Permissions-Policy, HSTS;
   `productionBrowserSourceMaps: false`, `poweredByHeader: false`.
5. Front-end: `user-select: none` only on logos/graphics (text stays copyable). No right-click/F12 blocking (ineffective, hurts users).

Photos: watermark on the 960/1920 sizes (drawn in the browser before upload); files are served only by the Worker (`/media/public/...`).

### Cloudflare security settings (Dashboard, ทีละขั้น)
ทำบนโดเมนจริง (zone) — workers.dev ใช้ WAF ไม่ได้ ต้องผูก custom domain ก่อน: Workers → utd-student-council → Settings → Domains & Routes → Add custom domain
1. **WAF Managed Rules**: Security → WAF → Managed rules → เปิด *Cloudflare Managed Ruleset* (Free plan: *Free Managed Ruleset* เปิดอยู่แล้ว)
2. **Bot Fight Mode**: Security → Bots → Bot Fight Mode → On
3. **Block AI Bots**: Security → Bots → *Block AI bots* → On (เสริม robots.txt + proxy.ts)
4. **Rate limiting rules**: Security → WAF → Rate limiting rules → Create
   - `/api/*`: URI Path starts with `/api/` → 60 requests / 1 minute / IP → Block 1 minute
   - sign-in: URI Path equals `/auth/google` หรือ starts with `/api/auth/` → 10 requests / 1 minute / IP → Block 10 minutes
     (แอปจำกัด 5 ครั้ง / 15 นาทีเองอยู่แล้ว ชั้นนี้ช่วยหยุดก่อนถึง Worker)
5. **Under attack**: Security → Settings → Security level → *I'm under attack* (ชั่วคราว)
6. Security headers (CSP nonce, HSTS, ...) ยังตั้งในแอป (`proxy.ts`, `next.config.ts`) — ไม่ต้องตั้งใน Cloudflare
7. IP ผู้ใช้มาจาก `cf-connecting-ip` (Cloudflare ตั้งให้ ปลอมไม่ได้) ไม่ใช่ `x-forwarded-for`

### Honest limits
This raises the cost of scraping; it cannot make it impossible. Anyone who renders the page in a normal browser can read what a
visitor can read. The Workers rate-limit binding counts per Cloudflare location (not globally); the WAF rules above are global.
