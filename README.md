# สภานักเรียนโรงเรียนอุตรดิตถ์ — Website

Next.js (App Router, TypeScript) + Tailwind v4 + Motion + GSAP ScrollTrigger. Design tokens mirror the Figma file
`UTD Student Council Website`. Decisions and placeholders: see [NOTES.md](NOTES.md).

## Run

```bash
npm install
cp .env.example .env.local   # set APP_SECRET at minimum for `npm run build && npm start`
npm run dev                  # http://localhost:3000
npm run build && npm start   # production (needs APP_SECRET, Supabase, Turnstile — see below)
```

`npm run dev` works with no env at all (in-memory rate limit, voice saved to `.data/voice.jsonl`, Turnstile skipped).

## ตั้งค่า env หาจากไหน

คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า (บนโฮสต์ใส่ที่ Environment Variables) — สถานะทุกค่าดูได้ที่ `/admin/setup` (admin เท่านั้น ไม่แสดงค่าจริง)
และตอน `npm run dev` ถ้าค่าใดขาดจะมีคำเตือนใน terminal

### `APP_SECRET` — จำเป็นตอนใช้งานจริง · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** กุญแจลับของแอป ใช้เซ็นโทเคน API อายุสั้น และเป็นเกลือ (salt) ตอนแปลง IP เป็นค่าแฮช
- **หาจากไหน:** สร้างเอง: รันคำสั่ง node -e "console.log(require('crypto').randomBytes(32).toString('base64'))" แล้วคัดลอกผลลัพธ์มาใส่ (อย่างน้อย 32 ตัวอักษร) (https://nodejs.org/api/crypto.html#cryptorandombytessize-callback)
- **ถ้าไม่ใส่:** dev → ใช้คีย์ชั่วคราวสำหรับ dev · production → สร้างโทเคน API และบันทึกข้อความส่งเสียงถึงสภาไม่ได้ (error)

### `NEXT_PUBLIC_SITE_URL` — จำเป็นตอนใช้งานจริง · เปิดเผยได้
- **ใช้ทำอะไร:** ที่อยู่เว็บจริง ใช้ทำ sitemap, ลิงก์ hreflang และ Open Graph
- **หาจากไหน:** โดเมนของเว็บที่ deploy แล้ว เช่น https://council.utd.ac.th (Vercel → Project → Settings → Domains) ไม่ต้องมี / ท้าย (https://vercel.com/docs/projects/domains)
- **ถ้าไม่ใส่:** dev → ใช้ http://localhost:3000 · production → ลิงก์ใน sitemap/แชร์ชี้ไป localhost — ผิด

### `NEXT_PUBLIC_SUPABASE_URL` — จำเป็นตอนใช้งานจริง · เปิดเผยได้
- **ใช้ทำอะไร:** ที่อยู่โปรเจกต์ Supabase (ฐานข้อมูล + ระบบล็อกอิน + เก็บรูป)
- **หาจากไหน:** supabase.com → เลือกโปรเจกต์ → Project Settings → Data API → Project URL (รูปแบบ https://xxxx.supabase.co ไม่มี /rest/v1) (https://supabase.com/dashboard/project/_/settings/api)
- **ถ้าไม่ใส่:** dev → เว็บใช้ข้อมูลตัวอย่างจาก content/seed.json, หลังบ้านเข้าไม่ได้ · production → ไม่มีข้อมูลจริง, ล็อกอินไม่ได้

### `NEXT_PUBLIC_SUPABASE_ANON_KEY` — จำเป็นตอนใช้งานจริง · เปิดเผยได้
- **ใช้ทำอะไร:** คีย์สาธารณะของ Supabase ใช้อ่านข้อมูลที่อนุมัติแล้ว (ถูกจำกัดด้วย RLS)
- **หาจากไหน:** supabase.com → Project Settings → API Keys → Publishable key (หรือแท็บ Legacy → anon public) (https://supabase.com/dashboard/project/_/settings/api-keys)
- **ถ้าไม่ใส่:** dev → เหมือนกรณีไม่มี SUPABASE_URL · production → ไม่มีข้อมูลจริง, ล็อกอินไม่ได้

### `SUPABASE_SERVICE_ROLE_KEY` — จำเป็นตอนใช้งานจริง · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** คีย์สิทธิ์สูงสุดของ Supabase (ข้าม RLS) ใช้เฉพาะฝั่งเซิร์ฟเวอร์หลังตรวจสิทธิ์แล้ว: อนุมัติ, อัปโหลดรูป, บันทึกข้อความส่งเสียง
- **หาจากไหน:** supabase.com → Project Settings → API Keys → Secret key (หรือแท็บ Legacy → service_role) — ห้ามใส่ในโค้ดฝั่งหน้าเว็บเด็ดขาด (https://supabase.com/dashboard/project/_/settings/api-keys)
- **ถ้าไม่ใส่:** dev → ข้อความ /voice เก็บลงไฟล์ .data/voice.jsonl, หลังบ้านอนุมัติ/อัปโหลดไม่ได้ · production → ส่งเสียงถึงสภาไม่ได้ (ปฏิเสธ), หลังบ้านใช้ไม่ได้

### `UPSTASH_REDIS_REST_URL` — ไม่บังคับ · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** ที่อยู่ Redis สำหรับจำกัดจำนวนคำขอ (rate limit) และรายการ IP ที่ถูกแบน ให้ใช้ร่วมกันทุกเซิร์ฟเวอร์
- **หาจากไหน:** upstash.com → Redis → Create Database → หน้า Database → แท็บ REST API → UPSTASH_REDIS_REST_URL (ขึ้นต้น https:// ไม่ใช่ rediss://) (https://console.upstash.com/redis)
- **ถ้าไม่ใส่:** dev → ใช้ตัวจำกัดในหน่วยความจำ (พอสำหรับเครื่องเดียว) · production → จำกัดคำขอแยกกันแต่ละเซิร์ฟเวอร์ — กันบอทได้น้อยลง

### `UPSTASH_REDIS_REST_TOKEN` — ไม่บังคับ · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** โทเคนเขียน/อ่าน Redis ข้างบน
- **หาจากไหน:** upstash.com → หน้า Database → แท็บ REST API → UPSTASH_REDIS_REST_TOKEN (ใช้ Token ปกติ ไม่ใช่ Readonly Token) (https://console.upstash.com/redis)
- **ถ้าไม่ใส่:** dev → ใช้ตัวจำกัดในหน่วยความจำ · production → เหมือนกรณีไม่มี URL

### `NEXT_PUBLIC_TURNSTILE_SITE_KEY` — จำเป็นตอนใช้งานจริง · เปิดเผยได้
- **ใช้ทำอะไร:** คีย์สาธารณะของ Cloudflare Turnstile (กล่องยืนยันว่าไม่ใช่บอท) บนฟอร์มส่งเสียงถึงสภา
- **หาจากไหน:** dash.cloudflare.com → Turnstile → Add widget → ใส่โดเมนเว็บ → Site Key — ทดสอบได้ด้วยคีย์ 1x00000000000000000000AA (ผ่านเสมอ) (https://dash.cloudflare.com/?to=/:account/turnstile)
- **ถ้าไม่ใส่:** dev → ไม่แสดงกล่องยืนยัน · production → ไม่แสดงกล่องยืนยัน และฟอร์มส่งไม่ผ่าน

### `TURNSTILE_SECRET_KEY` — จำเป็นตอนใช้งานจริง · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** คีย์ลับของ Turnstile ใช้ตรวจผลยืนยันฝั่งเซิร์ฟเวอร์
- **หาจากไหน:** dash.cloudflare.com → Turnstile → widget ที่สร้าง → Secret Key — คีย์ทดสอบ 1x0000000000000000000000000000000AA (ผ่านเสมอ) (https://dash.cloudflare.com/?to=/:account/turnstile)
- **ถ้าไม่ใส่:** dev → ข้ามการตรวจ · production → ปฏิเสธทุกการส่ง (fail closed)

### `ALLOWED_EMAIL_DOMAIN` — ไม่บังคับ · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** โดเมนอีเมลที่ล็อกอินหลังบ้านได้ (บัญชี Google ของโรงเรียน)
- **หาจากไหน:** โดเมนอีเมลโรงเรียน ค่าเริ่มต้น utd.ac.th — ใส่เฉพาะเมื่อต้องการเปลี่ยน (https://admin.google.com/)
- **ถ้าไม่ใส่:** dev → ใช้ utd.ac.th · production → ใช้ utd.ac.th

### `COUNCIL_EMAILS` — ไม่บังคับ · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** บัญชีล็อกอินหลังบ้านบทบาท "สภานักเรียน" (คั่นด้วยจุลภาค, ต่อท้าย :shared ถ้าเป็นบัญชีที่ใช้ร่วมกันหลายคน) ใช้ตอนรัน node scripts/seed-allowed-users.mjs เพื่อใส่ลงตาราง allowed_users ครั้งแรก หลังจากนั้นจัดการที่หน้า /admin/users
- **หาจากไหน:** รายชื่ออีเมลบัญชีสภานักเรียนจากผู้ดูแล (ห้ามใส่ในไฟล์ที่ commit) — ไม่ต้องตั้งบน Vercel (https://admin.google.com/)
- **ถ้าไม่ใส่:** dev → ไม่เพิ่มบัญชีอัตโนมัติ (เพิ่มเองที่ /admin/users ได้) · production → ไม่มีผล — แอปอ่านสิทธิ์จากตาราง allowed_users

### `ADMIN_EMAILS` — จำเป็นตอนใช้งานจริง · **ห้ามเปิดเผย**
- **ใช้ทำอะไร:** อีเมลผู้ดูแลระบบ (คั่นด้วย ,) — ได้สิทธิ์ admin ทันที และเป็นข้อยกเว้นเดียวที่ล็อกอินได้แม้ไม่ใช่โดเมนโรงเรียน (ต้องเป็นอีเมลที่ Google ยืนยันแล้ว)
- **หาจากไหน:** ใส่อีเมล Google ของผู้ดูแลเอง เช่น admin1@utd.ac.th,someone@gmail.com — เอาออกจากรายการ = ถอนสิทธิ์ทันที (https://supabase.com/dashboard/project/_/auth/users)
- **ถ้าไม่ใส่:** dev → ไม่มีใครเป็น admin · production → ไม่มีใครเป็น admin — ตั้งสิทธิ์คนอื่น/ปีการศึกษาไม่ได้

### Google OAuth — ตั้งใน Supabase (ไม่ใช่ค่าใน .env)
- **ใช้ทำอะไร:** ล็อกอินด้วย Google (ไม่ใช่ค่าใน .env — ตั้งที่ Supabase)
- **วิธีตั้ง:** 1) console.cloud.google.com → APIs & Services → Credentials → Create credentials → OAuth client ID → Web application → Authorized redirect URI: https://<project>.supabase.co/auth/v1/callback  2) supabase.com → Authentication → Sign In / Providers → Google → เปิด แล้วใส่ Client ID + Client Secret  3) Authentication → URL Configuration → Site URL = NEXT_PUBLIC_SITE_URL และเพิ่ม <SITE_URL>/auth/callback ใน Redirect URLs
- **ถ้าไม่ตั้ง:** ปุ่มเข้าสู่ระบบใช้ไม่ได้

## Scraping protection (what exists)

1. **`proxy.ts`**: blocks empty UA, scraper tools (curl, wget, python-requests, scrapy, HTTrack, Go-http-client, headless...) and AI
   crawlers with 403; rate limit per IP (pages 60/min, API 20/min -> 429 + `Retry-After`); verifies Googlebot/Bingbot by reverse DNS;
   honeypot + scanner paths ban the IP for 1h; per-request CSP nonce.
2. **`app/robots.ts`**: search engines allowed; AI/dataset crawlers disallowed; `/api/`, `/admin/`, `/_hp/` disallowed. `X-Robots-Tag: noai, noimageai`.
3. **APIs**: no endpoint returns everything (page size capped at 20); requires same-origin + 5-minute HMAC token from `/api/token`.
   Member data is name/role/grade only. `/voice` stores IP as a salted hash, with honeypot field, zod validation, 3 submits / 10 min / IP, Turnstile.
4. **Headers** (`next.config.ts` + `proxy.ts`): CSP, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, nosniff, Referrer-Policy, Permissions-Policy, HSTS;
   `productionBrowserSourceMaps: false`, `poweredByHeader: false`.
5. Front-end: `user-select: none` only on logos/graphics (text stays copyable). No right-click/F12 blocking (ineffective, hurts users).

Not implemented: image watermarking and hotlink protection (no real photos yet — add when images exist; `next/image` is ready).

### Extra hardening on Vercel
Enable **Vercel Firewall** (Project -> Firewall): add a rate-limit rule and turn on **Attack Challenge Mode** when under attack;
consider Vercel BotID on `/voice` in addition to Turnstile.

### Honest limits
This raises the cost of scraping; it cannot make it impossible. Anyone who renders the page in a normal browser can read what a
visitor can read. In-memory rate limiting is per-instance — configure Upstash in production.
